- Phone normalization: Egyptian numbers only (`20` prefix, `010`/`011`/`012`/`015` patterns)
- Button label: "فتح واتساب"
- Button appears on: sales invoice, customer statement, purchase invoice, supplier statement
- Button hidden when: phone is null, empty, or fails normalization
- Daily report: intentionally excluded (no owner phone setting exists)
- Message template: includes document type, number, date, customer/supplier name, and "مرفق" indicator
- URL scheme: `https://wa.me/{phone}?text={encoded}` (app first), fallback `https://web.whatsapp.com/send?...`
- **No automatic sending, no API tokens, no backend, no browser automation.**
- The `README-AR.txt` (generated by script) does NOT mention WhatsApp, but the detailed Arabic docs correctly document it.

## Non-Blocking Notes

1. **README-AR.txt omission**: The `README-AR.txt` (auto-generated by `create_pilot_delivery_package.ps1`) does not mention PDF export or WhatsApp sharing. The detailed `docs/OWNER-QUICK-START-AR.md` and `docs/PILOT-RELEASE-NOTES-AR.md` both document these features accurately. This is a minor gap in the script-generated quick-start, not a defect.

2. **In-memory storage**: All data is session-only. Data does not persist between launches. The backup/restore mechanism is the only data transfer method. This is a known pilot limitation documented in handoff notes.
