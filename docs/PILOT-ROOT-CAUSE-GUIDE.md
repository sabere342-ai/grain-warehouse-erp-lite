# Pilot Root Cause Guide

Use these definitions only after real feedback is received and reviewed. Do not assign a root cause without evidence.

## User Training
The application behaves according to accepted rules, but the user needs clearer instruction, practice, or onboarding.

## Data Entry
The reported result comes from values entered incorrectly, missing required business data, duplicated entry, or selecting the wrong option.

## UX
The workflow, wording, layout, or interaction may lead to confusion even if the underlying data and business logic are correct.

## Business Rule
The observation relates to an accepted or disputed business policy, operating rule, permission rule, pricing rule, or workflow rule.

## Accounting
The observation relates to customer balances, supplier balances, inventory valuation or quantity truth, transaction effects, reversals, or report consistency with source records.

## Performance
The observation relates to slow response, delayed screen updates, long-running operations, export speed, startup time, or resource usage.

## Environment
The observation relates to the local Windows machine, operating system settings, permissions, antivirus behavior, file access, display settings, printer/PDF viewer behavior, or machine-specific conditions.

## Installation
The observation relates to opening the delivered package, missing runtime files, install/copy location, first launch, shortcuts, or owner handoff setup.

## Unsupported Usage
The observation comes from using the system outside the accepted scope or documented operating rules.

## Unknown
The evidence is not enough to identify a root cause yet.

Use Unknown rather than guessing.
