## 6. Current architecture evidence

### 6.1 Selected direct account-statement read

The selected production file is:

`lib/features/financial_reports/account_statement_report_screen.dart`.

The sole selected seam is the direct logo-byte lookup inside
`_AccountStatementReportScreenState._exportPdf`:

```text

  identity.logo!.managedFileName,
)
```

Current source proves that the method:

1. returns immediately when `_report == null`;
2. loads business identity through
   `AppRepositories.businessIdentityRepository.loadIdentity()`;
3. gates the logo read with
   `identity.hasLogo && identity.logo != null`;
4. passes `identity.logo!.managedFileName` to the selected read;
5. passes `_report!`, the loaded identity, and nullable logo bytes to
   `FinancialReportPdfBuilder.buildAccountStatementReport`;
6. forwards the returned file to the existing saved-path notification; and
7. contains failures under the existing Arabic PDF failure snackbar.

The current PDF builder uses the supplied report, identity, and nullable logo
bytes, retains the existing Arabic/RTL layout, saves under the existing
`Exports` directory with `PdfFileNaming.accountStatementReport`, writes the
bytes, and returns the file. Those surrounding behaviors are evidence and are
not migration scope.
