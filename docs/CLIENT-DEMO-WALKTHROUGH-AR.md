# سيناريو العرض التجريبي المُحكم — برنامج غلال

> الإصدار: 1.0.0+1 | تاريخ البناء: 2026-07-25 | المنصة: Windows x64

---

## الغرض

هذا السكريبت يُستخدم لإجراء عرض تجريبي مُحكم للعميل. يشمل خطوات واضحة مع فصل بين إجراءات المشغّل وتأكيدات العميل.

**المشغّل:** مسؤول العرض (المطور أو مسؤول التسليم).
**العميل:** المالك المرتقب للنظام.

---

## قبل بدء العرض (قائمة التحقق)

- [ ] تم نسخ حزمة التسليم إلى جهاز العرض (ليس من مجلد التطوير).
- [ ] تم التحقق من سلامة الملفات (checksums.sha256).
- [ ] البرنامج يُشغّل بنجاح من مجلد النسخة.
- [ ] لا توجد بيانات حقيقية للعملاء في النظام (بيانات وهمية فقط).
- [ ] جهاز العرض مُوصّل بالكهرباء (لا يعتمد على البطارية).
- [ ] تم إعداد شاشة العرض بحيث يراها العميل بوضوح.
- [ ] سجل المشاكل (`OWNER-TRIAL-INCIDENT-LOG-AR.md`) مفتوح وبجانبك.
- [ ] أخذت نسخة احتياطية من أي بيانات سابقة إن وجدت.

## سيناريو العرض

### المرحلة 1: التشغيل والهوية (5 دقائق)

| الخطوة | إجراء المشغّل | النتيجة المتوقعة | تأكيد العميل |
|--------|---------------|-------------------|-------------|
| 1.1 | افتح مجلد التسليم وشغّل `grain_warehouse_erp_lite.exe` | قد تظهر رسالة أمان Windows — اختر "更多信息" ثم "تشغيل على أي حال" | يرى العميل رسالة الأمان ويفهم أنها طبيعية |
| 1.2 | سجّل الدخول بحساب المالك (`01000000000` / `owner123`) | تظهر الشاشة الرئيسية (لوحة التحكم) | يرى العميل الشاشة الرئيسية بالعربية |
| 1.3 | أظهر عنوان النافذة والشارة (Windows title bar) | يظهر اسم "غلال" أو "Grala" في شريط العنوان | يؤكد العميل ظهور الهوية |
| 1.4 | افتح شاشة الإعدادات وأظهر اسم المنشأة والشعار | تظهر إعدادات المنشأة (يمكن إدخال اسم تجريبي) | يرى العميل إمكانية تخصيص الهوية |

**إذا فشلت الخطوة 1.1:** تحقق من أن الجهاز يدعم Windows 10/11 64-bit. لا تُكمل العرض إذا لم يشغّل البرنامج.

### المرحلة 3: العمليات التجارية (15 دقيقة)

| الخطوة | إجراء المشغّل | النتيجة المتوقعة | تأكيد العميل |
|--------|---------------|-------------------|-------------|
| 3.1 | سجّل **شراء**: المورد "أحمد المورد"، الصنف "قمح تجربة"، الكمية 5000 كجم، السعر 800 | يتم حفظ الشراء وتظهر فاتورة | يرى العميل فاتورة الشراء |
| 3.2 | افتح شاشة **المخزون** | كمية القمح = 5000 كجم | يتأكد العميل من زيادة المخزون |
| 3.3 | سجّل **بيع آجل**: العميل "سعيد العميل"، الصنف "قمح تجربة"، الكمية 2000 كجم، السعر 1000 | يتم حفظ البيع وتظهر فاتورة | يرى العميل فاتورة البيع |
| 3.4 | افتح شاشة **المخزون** | كمية القمح = 3000 كجم (نقص 2000) | يتأكد العميل من نقص المخزون |
| 3.5 | افتح **كشف حساب العميل** "سعيد العميل" | رصيد العميل = 2,000,000 قرش (مدين) | يرى العميل رصيد العميل |

**إذا فشلت أي خطوة في المرحلة 3:** أوقف العمليات التجارية وسجل المشكلة. لا تُكمل بعمليات مالية أخرى.

## قائمة تحقق سريعة للعميل

- [ ] تم تشغيل البرنامج من حزمة التسليم.
- [ ] تظهر الشاشة الرئيسية بالعربية.
- [ ] يمكن إضافة أصناف وموردين وعملاء.
- [ ] يمكن تسجيل شراء وبيع.
- [ ] المخزون يتحدث تلقائياً مع كل حركة.
- [ ] يمكن تسجيل تحصيل ودفع.
- [ ] يمكن تسجيل مصروف.
- [ ] التقرير اليومي يعرض ملخصاً صحيحاً.
- [ ] كشف حساب العميل والمورد صحيح.
- [ ] النسخ الاحتياطي يعمل.
- [ ] لا توجد صفحات "قيد التنفيذ" أو شاشات مضللة.
- [ ] الهوية (الاسم، الشعار، العنوان) واضحة وصحيحة.

---

## ماذا تفعل إذا ظهر خطأ

1. **توقف** عن إدخال بيانات جديدة.
2. **صوّر** الشاشة التي تظهر فيها المشكلة.
3. **اكتب** الخطوة التي حدثت فيها المشكلة في سجل المشاكل.
4. **لا تحاول** تعديل قاعدة البيانات يدوياً.
5. **لا تسترجع** نسخة احتياطية فوق بيانات موجودة.
6. **تابع** العرض من الخطوة التالية إن أمكن (إذا لم تكن المشكلة حرجة).
7. **أبلغ** المطور فوراً إذا كانت المشكلة حرجة (تؤثر على الأرصدة أو المخزون).

## معايير قرار العميل

| القرار | الشرط |
|--------|-------|
| **مقبول** | جميع الخطوات الأساسية نجحت، لا مشاكل حرجة، الهوية صحيحة |
| **مقبول مع ملاحظات** | معظم الخطوات نجحت، مشاكل متوسطة أو منخفضة قابلة للحل |
| **غير مقبول** | مشاكل حرجة في الأرصدة أو المخزون، أو البرنامج لا يعمل |
| **يحتاج مراجعة إضافية** | جلسة غير مكتملة، أو معلومات غير كافية لاتخاذ القرار |
