# Roadmap Risk Register — Grain Warehouse ERP Lite

| ID | Severity | Likelihood | Affected Area | Description | Prevention | Detection | Recovery | Required Test | Owning Phase |
|---|---|---|---|---|---|---|---|---|---|
| RISK-001 | Critical | High (without idempotency) | Financial accounts, customer/supplier ledgers | Same operation posted twice due to network retry or UI double-click | Idempotency keys, server-side duplicate check | Balance drift detection, audit log comparison | Manual correction entry with permission | Idempotency test for each operation type | Track F (Offline Sync) |
| RISK-002 | Critical | Medium | All financial data | Some entities sync while others fail, breaking atomicity | Transaction groups, server-side atomic commands | Consistency checks, entity relationship validation | Full re-sync of affected transaction group | Partial sync simulation test | Track F (Offline Sync) |
| RISK-003 | High | Medium (multi-device) | Inventory, sales | Two devices sell last remaining stock simultaneously | Server-side stock validation, reservation | Negative stock alert | Cancellation or restock | Concurrent sale conflict test | Track G (Multi-Device) |
| RISK-004 | Critical | Medium | Customer accounts, financial accounts | Same customer debt collected twice from different devices | Idempotency keys, server-side balance check | Customer balance mismatch | Reversal entry | Duplicate collection prevention test | Track F (Offline Sync) |
| RISK-005 | Critical | Medium | Supplier accounts, financial accounts | Same supplier debt paid twice | Idempotency keys, server-side balance check | Supplier balance mismatch | Reversal entry | Duplicate payment prevention test | Track F (Offline Sync) |
| RISK-006 | Critical | Low (single device), High (multi-device) | All financial accounts | Account balance does not match sum of ledger entries | Ledger-only balance calculation, never store computed balance | Reconciliation check test | Recalculate from ledger, create correction entry | Balance invariant test | Track A (Financial Foundation) |
| RISK-007 | High | Medium | Authorization | Device has old permissions after user role changed on another device | Server-side permission check, session validation | Permission audit log | Force re-authentication | Permission change propagation test | Track E (Cloud Foundation) |
| RISK-008 | Critical | Low | Financial accounts, customer/supplier ledgers | Cancellation reversal creates wrong amount or wrong direction | Reversal derived from original entry, not user input | Balance verification after reversal | Manual correction entry | Reversal symmetry test for each operation | Track B (Transaction Integration) |
| RISK-009 | High | Medium | Customer/supplier accounts | Payment allocated to wrong invoice or wrong customer | Server-side allocation validation, source document linking | Statement reconciliation | Reallocation entry | Payment allocation test | Track B (Transaction Integration) |
| RISK-010 | Critical | Low | All data | Local-to-cloud migration corrupts or loses data | Pre-migration backup, validation, rollback plan | Row count and totals comparison | Restore from pre-migration backup | Migration validation test | Track I (Migration) |
| RISK-011 | Critical | Low (single tenant), Medium (multi-tenant) | Security, all data | One tenant's data visible to another | Tenant isolation, RLS policies | Cross-tenant access test | Immediate isolation fix, incident response | Tenant isolation test | Track E (Cloud Foundation) |
| RISK-012 | High | Low | Authentication, all data | Stolen session token used to access system | Secure token storage, short-lived tokens, refresh rotation | Anomalous access patterns | Token revocation, forced re-auth | Token lifecycle test | Track E (Cloud Foundation) |
| RISK-013 | High | Low | Sync, all operations | Offline queue data corrupted or lost | Durable local storage, checksums | Queue integrity check on app start | Re-queue from last known state | Queue persistence test | Track F (Offline Sync) |
| RISK-014 | Medium | High | Timestamps, ordering | Device clocks differ, causing incorrect ordering | Server timestamps for authoritative ordering | Clock skew detection | Re-order by server timestamp | Clock skew test | Track F (Offline Sync) |
| RISK-015 | Medium | Low (single device), Medium (multi-device) | Document history, reports | Two devices generate same document number | UUID-based IDs, server-assigned sequential numbers | Duplicate number check | Re-number on sync | Number collision test | Track F (Offline Sync) |
| RISK-016 | Medium | Medium | Backup/restore | New backup format incompatible with old restore | Versioned backup format, backward compatibility | Restore compatibility test | Format converter or manual migration | Backup version compatibility test | Track A (Financial Foundation) |
| RISK-017 | Medium | High | Schedule, budget | Mobile app grows beyond agreed scope | Clear scope definition, phase gates | Scope review at each phase | Reduce scope, defer features | Scope compliance review | Track H (Mobile) |
| RISK-018 | Medium | Medium | Budget, sustainability | Cloud hosting costs exceed budget | Cost estimation, tiered pricing | Monthly cost review | Optimize, downscale, or adjust pricing | Cost projection review | Track E (Cloud Foundation) |
| RISK-019 | Low | Medium | Long-term maintenance | Deep dependency on specific cloud provider | Abstraction layers, standard APIs | Architecture review | Migration to alternative provider | Provider abstraction test | Track E (Cloud Foundation) |
| RISK-020 | Medium | High | User adoption | Owner cannot operate system correctly | Arabic documentation, guided trials, video tutorials | Pilot observation, feedback | Additional training, UI improvements | Owner acceptance test | Track I (Migration & Pilot) |
| RISK-021 | Medium | Medium | Operations, reliability | No visibility into system health or errors | Monitoring dashboard, alerting | Incident reports | Implement monitoring | Monitoring coverage review | Track E (Cloud Foundation) |
